# 编辑边界校准案例

## 标题预筛的反例

标题承诺的是文章的主题，不是编辑随后可以虚构的切口。融资额、客户数或任职履历可以成为事实背景，但如果标题主要靠这些信息吸引人，须先解释目标读者为什么关心，而不能用正文的一小段方法强行包装。

同时保留抽象标题中的强正例：《未来的某种形状：私人定制数字化产品市场》与《AI 真正有用，不是会得多，而是能把事情办成》都获用户明确肯定。所以标题阶段不能封杀“未来”“市场”“系统”，也不能把选题缩成只有操作教程。信息不足时进入待全文判断，不假装已否决。

本文件用历史正反例校准边界。案例用于解释原则，不用于按标题模仿或建立永久类别禁令。

## 个人经历

### 可选：普遍痛点推动的真实产品经历

“良配”访谈从普通人的婚恋痛点出发，产品有自然吸引力，经历、失败和取舍围绕同一问题推进。去掉创始人的家庭照片和身份光环，产品定义、匹配机制、成功标准与退款矛盾仍可成立。

### 不选：价值绑定私人项目资产

个人 App 复盘、客户现场流程或公司内部案例，如果主要价值来自作者自己的项目路径、截图、收入、客户数据和品牌经历，Stephen 很难独立重建文章。文章真实、质量高，也可能不适合二创。

边界：不要把“第一人称”当缺陷。判断论证是否能脱离专属资产。

## 访谈和演讲

### 可选：围绕具体产品决策持续推进

KiKi、Claude Code 团队、千问办公和百度网盘产品负责人的优质材料，都围绕明确产品问题、用户任务、失败和取舍连续展开。人物身份增加可信度，但价值来自正文里的决策链。

### 不选：名人闲聊和宏观机会判断

名气很大的受访者如果主要谈成长经历、工业革命、时代机会、平台战局或“未来会怎样”，仍然可能浅、散、难以落成一篇对读者有用的文章。

边界：权威身份和完整逐字稿只证明值得阅读，不证明适合写作。

## 技术深度

### 可选：稀缺而可迁移的判断框架

美团两年 Agent 评测实践虽然有一定门槛，但“结果、轨迹、组件”形成了稀缺且可迁移的评估框架，因此可以作为受控例外。

### 不选：理解依赖实现细节

正文若主要围绕 HTTP、GPU 缓存、node_modules、pnpm、CI/CD、CUDA、终端快捷键或论文指标展开，普通读者必须理解大量专业概念才能跟上主线，即使文章高质量也不适合。

有些材料没有连续代码块，仍可能被数十个缩写、系统名、路由名和工程标识主导。如果读者要先学会这套专业语言才能理解文章的核心价值，也属于实质技术门槛，不能用一句通俗总结来掩盖。

同理，一个案例若同时依赖虚拟机、容器、VPN、脚本、爬虫、接口监听等多种实施概念，即使文章最后提炼出一句简单方法，原材料的理解和复用成本仍然过高。

边界：不是看有没有技术词，而是看技术背景是否成为理解和复用的前置条件。

## 产品与任务

### 可选：产品有吸引力，任务具体

能帮助读者完成客户拜访、找回工作上下文、阅读后回到原文、检查 AI 是否推荐自己的产品等材料，任务和收益具体，容易形成自然文章。

### 不选：无趣产品的负面切口

产品本身缺少使用价值时，“为什么它不工作”不能自动成为选题。购物 Agent 架构、OpenWorker 失败或某些小众产品，即使原文质量不错，也可能没有读者吸引力。

边界：先判断产品和问题是否值得关注，不能靠批评制造价值。

## AI 写作与信息密度

### 可选：结构清楚且证据扎实

清单、分段和框架可以帮助阅读。只要每个部分都有真实事实、失败、条件和作者判断，结构本身不是问题。

### 不选：结构代替内容

多级编号、整齐分类、口号式小标题、密集引号和抽象术语，如果背后只有常识、重复解释和漂亮包装，就属于低信息密度材料。AI 痕迹是提示，缺乏增量才是淘汰原因。

边界：案例的存在不等于证据成立。案例若只负责说明作者刚提出的框架，没有结果、反例或可核验变化，整篇仍然可能泛泛而谈。

## 历史背景与当前价值

### 可选：历史直接解释今天的机制

历史材料可以帮助读者看懂一个今天仍在发生的问题，但必须快速落到当前产品、用户任务或可验证机制，并提供新的事实或取舍。

### 不选：历史沿革占据正文主体

公司、人物、技术或概念的沿革如果占去大部分正文，而当前产品价值、用户改变和可执行判断只在结尾出现，材料再完整也不适合当前选题。

边界：不按年代久远与否判断，而看删掉历史段落后，正文是否还剩足以独立成文的当前增量。

## Workflow 平台与工作方法

### 可选：现代 Agent 工作流中的通用方法

材料围绕任务验收、失败隔离、状态回读、权限边界或异步协作展开，即使提到工作流，价值也来自可迁移的方法和当前 Agent 能力。

### 不选：传统节点式 Workflow 平台教程

以 Coze、Dify、n8n 等节点式编排平台为主体的搭建、插件和模板内容已经失去当前选题价值，不再推荐。

边界：淘汰的是这类平台作为选题主体，不是“工作流”三个字，也不能误杀迁移离开旧平台或讨论现代 Agent 执行闭环的材料。

## 新闻、翻译和整理

### 可选：整理者提供独立理解

中文二手材料若核对了原始来源，并增加自己的实测、解释、判断或因果组织，可以成为高效二创底稿。

### 不选：通稿、纯翻译与拼盘

记者报道、官方材料、AI 摘要或播客翻译若只是重排公开信息，没有整理者自己的体感与判断，不因篇幅长、数字多、来源权威而放行。

## 风险新闻与用户安全

### 不选：实验室安全与对齐风险

OpenAI、Anthropic 等前沿实验室的模型越界、攻击、红队、沙箱逃逸和对齐声明，即使事故报告完整、条件限定严谨，也往往只增加风险感知，难以转化成当前读者的具体收获，后续不再推荐。

### 可选：普通用户能直接采取行动的安全材料

若材料围绕普通用户真正面对的账号、转账、隐私、诈骗或文件权限风险，并给出能立即执行和验证的防护动作，仍可继续终审。

边界：不是封杀“安全”两个字，而是判断文章最终留给读者的是实验室风险新闻，还是可直接使用的自我保护。

## 图片与逐字稿

- 图片多不是自动淘汰；要看文字论证是否离开图片仍成立。
- 逐字稿完整不是自动入选；还要检查信息密度和连续判断。
- 逐字稿交付前必须恢复可读性，不能把无标点字幕墙交给用户。

### 可选：声音材料的论证在文字中完整成立

访谈、演讲或播客虽然来自音视频，但如果核心事实、反例、条件和因果链都能从整理后的文字中独立理解，仍可作为文章材料。

### 不选：关键证据只在画面或代码里

全流程操作视频即使有完整逐字稿，如果论证持续依赖“现在打开”“点击这里”“可以看到”等画面动作，文字载体不能保留原材料的完整证据。同理，文章若用大段代码和实现片段承担关键推理，不能只抽出一个产品金句就宣称适合小白读者。

边界：淘汰的是文字无法独立承载关键证据，不是视频、截图或代码这些媒介本身。少量图示或短代码只要不阻碍文字主线，不应被一起误杀。

## 精确状态，不扩张成原则

以下信息属于当前选题资产状态，只做精确匹配或主题族去重：

- 已经写过的文章和主题。
- 暂缓的普通 WorkBuddy 岗位教程。
- 当前不认可的具体产品。
- 明确屏蔽的来源或个人 IP。

这些状态不能扩张为“所有类似产品、作者或主题永久不选”。

## 日常 Skill 的净提效成本

观察：一批面向日常使用的 GitHub Skill 全部被淘汰，其中唯一有解释的反馈是“配置略微复杂，而且要付费”；其余空备注只记录为当前候选结果。

类型：`hypothesis`。单批反馈不足以把“付费”或“需要配置”升级为主观硬门槛。

稳定原则：推荐日常提效 Skill 时，不能只写最终能力，还要核算首次配置、账号与密钥、持续费用、人工确认和故障维护。优先让普通中文用户少配置、零额外付费，并能在第一次运行中得到可见结果的方案。

边界反例：付费本身不等于不值得。如果节省的重复劳动显著、费用和权限透明、免费替代确实更差，且中文用户能够稳定完成配置，仍可进入终审。

落实位置：当前只作为人工终审和排序假设，不进入自动硬拦截；等待不同主题的后续反馈验证。
