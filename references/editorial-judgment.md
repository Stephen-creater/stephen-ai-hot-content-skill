# 编辑判断标准

本文件记录从 Stephen 历次审核中总结出来的稳定判断。它回答“怎么判断一篇材料值不值得推荐”，不放具体链接、当日补丁和执行命令。

## 一句话目标

找这样的材料：围绕目标读者真正关心的 AI 问题，原文有足够新的事实和真实取舍，Stephen 去掉作者专属素材后能重写成自己的文章，改动不大就能发，读者读完能做成一件事或改掉一个误解。

目标读者：偏小白的中文 AI 使用者，产品、运营和管理者，知识工作者和内容创作者。

## 怎么打分

六个维度各打 0、1、2 分：

- **2 分**：明显做到，能引用正文说明。
- **1 分**：部分做到，或有明显短板。
- **0 分**：基本没做到。

**总分至少 8 分（满分 12），且“读者改变”“干货含量”都不是 0 分，就推荐。** 不要求每项都好。一篇文章击中大部分要求，就比一篇四平八稳但没有干货的文章更值得推荐。

打分时每项都要引用正文事实，不接受“深度好文”“作者权威”这类空话。最后写出最大疑点，并说明为什么仍然放行。

## 六个维度

### 1. 选题吸引力：读者会不会想点开

先判断这个题值不值得写，再判断文章写得好不好。

2 分的样子：
- 普遍存在的生活、学习或工作痛点；
- 有意思、真有人想用的产品；
- 一个不需要背景知识就能懂的具体矛盾或决策；
- 重大产品变化能落到用户每天要做的事上，不只是参数、榜单或公司之间的竞争。

0 分的样子：
- 产品本身无趣，只能从“为什么不好用”切入；
- 赛道极窄，换到大众场景也很勉强；
- 只讲融资、合作、比赛、跑分、硬件参数；
- 题目很大，找不到一个能一路讲下去的具体问题；
- 主体是大厂产品演进和战略预测，读者拿不到能直接用的东西；
- 主体是前沿实验室的安全、对齐、攻击风险，读者只能多一份担忧。

### 2. 读者改变：读完能多做成什么事

合格的回答要能写成“之前怎么做或怎么想，之后怎么做或怎么想”。

算数的改变：
- 能完成一个以前做不成的任务；
- 会用一套可执行的方法或检查步骤；
- 纠正一个影响决策的重要误解；
- 看懂某个机制，从而更会选、会用、会评估 AI 产品。

不算数的：知道了一个故事、了解了趋势、觉得作者很厉害、自己听完有收获。这一项 0 分就不推荐。

### 3. 干货含量：原文有没有别处看不到的东西

看正文提供了什么，不看作者名气、篇幅和数字多少。

干货通常来自：
- 作者亲自做过之后的失败、调整和结果；
- 围绕同一个问题连续展开的完整访谈或演讲；
- 新机制，以及它的适用条件、反例和限制；
- 可核验的具体事实和有条件的取舍；
- 长期实践沉淀出的可复用方法。

干货少的常见样子：
- 新闻、官方通稿或翻译，只是把公开信息重排一遍；
- 问答松散，问题很多但没有连续的论证；
- 研究报告、人物引语和案例拼在一起，没有作者自己的判断；
- 工整的分类、清单和金句代替了事实和因果；
- 逐字稿很长、案例很多，却找不到一个能单独成文的新判断。

这一项 0 分就不推荐。

### 4. 可重写性：去掉原作者，还能不能写

做三步测试：
1. 隐去作者姓名和职业光环；
2. 拿掉私人截图、收入、客户资料、品牌宣传图和内部数据；
3. 把作者的专属项目换成公开事实，或 Stephen 能亲自验证的材料。

核心论证还在，真实经历就是证据；论证跟着塌了，就说明材料和作者绑得太紧。第一人称、创业经历、企业案例和访谈都不是扣分理由，关键看经验能不能抽成新的、可迁移的判断。

再做一步：去掉视频画面、操作演示或大段代码之后，关键步骤、失败和结果还能不能看懂。看不懂的话，逐字稿或一个简化切口不能证明它适合写成文章。

### 5. 长期价值：热度过去后还有没有人看

- 发布、故障、涨价这类即时事件，通常只在 5 天内有价值；
- 深度访谈、长期实测、机制解释和方法可以放宽时间；
- 旧材料如果只剩“当时发生过”，不再推荐；
- 技术预览版、马上会有破坏性更新的产品、已被更直接的能力替代的绕路方案，长期价值弱。

### 6. 改写成本：离能发还有多远

Stephen 要的是“改一改就能发”的材料。以他过去发布的文章为参照（标杆库建好后以 `references/benchmarks/` 为准）：

- **2 分**：结构和论证基本能沿用，只需去掉作者个人信息、换成 Stephen 的语气、补一两处说明；
- **1 分**：要重排结构，或补一部分论据和例子；
- **0 分**：只能借一个观点，文章要从头写。

## 三个容易混的区分

### 文章好不好，和适不适合

高质量的技术文章可能不适合目标读者；门槛低的文章也可能因为浅、泛、没新意而不适合。难度不是唯一的尺子，还要看有没有稀缺、可迁移的方法。

### 作者有经验，和离不开作者

真实经历通常让文章更可信。只有价值依赖作者身份、私人数据、专属图片或别人复现不了的环境时，才是重写的障碍。

### 表面特征，和实际问题

编号、引号、破折号、官方措辞和小标题，可能提示 AI 加工或信息密度低，但不能单独证明什么。最后要指出具体问题：重复、空泛、缺事实、缺因果，还是没有作者自己的判断。

## 审稿提示怎么核实

抓取结果里的审稿提示只是提醒你核实下面这些问题：

| 提示 | 要核实什么 |
|---|---|
| 技术词很多 | 读懂主线必须先懂这些词吗？能不能用几句话解释清楚而不丢论证？ |
| 个人经历很多 | 去掉私人素材后，还有没有可迁移的因果链？ |
| 访谈或逐字稿 | 是围绕一个问题推进，还是人生闲聊和宏观判断？ |
| 新闻或官方来源 | 有没有独立的实践、判断和能复用的机制？ |
| 产品介绍 | 产品值不值得关注？有没有品牌宣传以外的独立证据？ |
| 结构工整、像 AI 写的 | 结构背后有没有具体事实、失败和条件？ |
| 图片很多 | 离开图片，文字论证还站得住吗？ |
| 垂直行业 | 普通读者真的有这个需求吗，还是只能硬抽出一个通用切口？ |

## 判断纪律

- 排序分只决定先读什么，不决定最后推荐什么。
- 原文确实撑不起一篇好文章时就不推荐，不能用“有一个好观点”“可以补研究”“可以另拟切口”来补。正文长度只是最低要求，过了长度线仍要看论证是否完整；不能把摘要扩写来凑长度。
- 待定是单独的状态，不算入选也不算淘汰。
- 已写、已审、已被别的窗口交付的主题，优先级高于按钮上的入选状态。
- Stephen 只点按钮、没给原因时，记录结果，不推断新原则。
- 新反馈先按反馈学习规则处理，不直接写成关键词或类别禁令。
